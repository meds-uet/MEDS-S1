# M-07 Benchmark Harness

M-07 runs CoreMark and Dhrystone 2.1 on the temporary Spike-based bare-metal
platform. For commands and result interpretation, see [`README.md`](README.md).

## Implementation

- `coremark/` contains the CoreMark sources and RISC-V port in
  `barebones_riscv/`.
- `dhrystone/` contains the Dhrystone 2.1 sources and its app Makefile.
- `scripts/run_ci.py` runs both applications, calls the parsers, evaluates the
  regression gate, and writes reports/history under `build/bench/`.
- `scripts/parse_results.py` validates benchmark output and extracts metrics.
- `scripts/regression_gate.py` compares valid metrics with accepted history.
- `sw/bsp/crt0.S` and `sw/bsp/syscalls.c` provide the temporary shared runtime
  until the T-06 BSP implementation is integrated.

## Runtime configuration

The benchmark Makefiles target `riscv64-unknown-elf`, architecture
`rv64imac_zicsr_zifencei_zicbom_zicboz`, and ABI `lp64`. The documented local
toolchain is GCC 16.1.0, binutils 2.46, Newlib 4.6.0, and Spike 1.1.1-dev.
The toolchain must include the `rv64imac/lp64` Newlib multilib.

CoreMark uses `mcycle` timing, direct Spike UART output, and its validation
seeds. Dhrystone uses `mcycle`, writes through the temporary BSP syscalls, and
checks its final values in the parser before the result can be marked valid.

## Result and integration limits

CoreMark is accepted only when its correctness marker and CRC fields are
present. Dhrystone is accepted only when execution completes, all expected
final values match, and timing fields are positive and consistent. A parse
failure stops the runner before regression evaluation.

The measurements describe this temporary Spike environment, not MEDS-S1
hardware. The local `make bench` target runs the harness; the GitHub Actions
benchmark job is not enabled. The current root `bench-compare` target is not
implemented; the regression comparison performed by `make bench` is part of
`scripts/run_ci.py`.
